> **По-простому:** если внутри `computed` вызывать мутирующие методы вроде `sort()`, `reverse()` или `splice()`, ты меняешь **исходные** данные. Чтение computed может приводить к побочным эффектам.

## Код

```javascript
const state = reactive({ list: [3, 1, 2] })
const sorted = computed(() => state.list.sort((a, b) => a - b))
const safeSorted = computed(() => [...state.list].sort((a, b) => a - b))
```

## Как тестировать

- Сразу после открытия кейса `list` уже отсортирован — при первом обращении к `sorted.value` внутри computed был вызван `state.list.sort()`, который изменил исходный массив.
- Нажми «Добавить 4» или «Перемешать» и посмотри разницу: `sorted` мутирует `list`, `safeSorted` работает с копией и исходный массив не трогает.

Ожидаемо: мутирующие методы в computed меняют источник; копия перед сортировкой этого избегает.

## Почему так происходит?

В JavaScript методы `sort`, `reverse`, `splice` и им подобные изменяют массив **на месте**. Они не возвращают новый массив «рядом» — они переставляют элементы в том же объекте. Когда в computed мы пишем `state.list.sort(...)`, мы вызываем этот метод на реактивном массиве. Vue не копирует массив за тебя: computed просто выполняет твой код. Результат: исходный `state.list` после первого вычисления sorted оказывается отсортированным.

Это не особенность Vue, а поведение самих методов массивов. То же самое произошло бы с обычным объектом:

```javascript
const obj = { list: [3, 1, 2] }
const sorted = () => obj.list.sort((a, b) => a - b)
sorted()
console.log(obj.list)  // [1, 2, 3] — массив изменён
```

Computed по контракту принято считать «чистым»: результат зависит только от реактивных данных и не должен их мутировать. Иначе при каждом обращении к computed мы невольно меняем состояние приложения, что трудно отслеживать и отлаживать.

## Как писать безопасно

- Перед мутирующими операциями делай копию: `[...state.list].sort(...)` или `state.list.slice().sort(...)`.
- То же для `reverse`, `splice` и т.п.: работай с копией, а исходные данные не трогай.
- Если нужна «сортированная версия» исходного списка без изменения источника — в computed возвращай результат сортировки копии.

## Когда мутация в computed особенно коварна

- При первом обращении к computed (например, при рендере) массив мутируется; последующие чтения могут опираться на уже изменённые данные.
- Если на этот же массив подписаны другие computed или watch — они увидят изменение, вызванное «просто чтением» другого computed, что запутывает причинно-следственную связь.

## Что важно помнить

- `sort`, `reverse`, `splice` и подобные методы мутируют массив на месте.
- В computed используй копию: `[...list].sort()` вместо `list.sort()`.
- Чтение computed не должно менять исходные реактивные данные.
