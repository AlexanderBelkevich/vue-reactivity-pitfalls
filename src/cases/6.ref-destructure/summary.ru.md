> **По-простому:** если «вытащить» значение из `ref` (например, через деструктуризацию или присваивание `ref.value` в переменную), получаешь обычное значение. Реактивность остаётся только у самого ref; переменная с копией не связана с ним.

## Код

```javascript
const counter = ref({ value: 0 })
let plainValue = counter.value.value

counter.value.value++  // plainValue не изменится ❌
plainValue++           // counter.value.value не изменится ❌
```

## Как тестировать

- Нажми «counter.value.value++» — обновится отображение `counter.value.value`, а `plainValue` останется старым (пока не произойдёт другой ререндер).
- Нажми «plainValue++» — изменится только локальная переменная; `counter.value.value` и UI для неё не обновятся.
- Снова нажми «counter.value.value++» — произойдёт ререндер, и на экране `plainValue` покажет актуальное значение из последнего чтения при рендере.

Ожидаемо: `plainValue` — это снимок на момент чтения; связь с ref нет, UI «подхватывает» plainValue только при ререндере из-за других реактивных изменений.

## Почему так происходит?

`ref` хранит значение в свойстве `.value`. Когда мы пишем `let plainValue = counter.value.value`, мы один раз читаем текущее значение и записываем его в обычную переменную. Дальше эта переменная с ref никак не связана: это просто число (или объект, или строка). Изменение `counter.value.value` не обновит `plainValue`, а изменение `plainValue` не обновит ref.

Тот же принцип, что и с деструктуризацией `reactive`: мы читаем значение и работаем с копией. Реактивность есть только у «источника» — у ref. В шаблоне Vue отслеживает обращения к ref (и к reactive), поэтому при ререндере он заново прочитает `plainValue` — и на экране окажется то значение, которое переменная имела на момент этого рендера. Но сама переменная не реактивна: если её меняет только твой код и при этом не трогает ref, ререндер может произойти позже (из-за другого реактивного изменения) или не произойти в нужный момент.

## Отличие от reactive

С `reactive` мы делали `const { count } = state` и теряли связь с полем. С `ref` мы делаем `const x = ref.value` (или вложенное поле `counter.value.value`) — и теряем связь с ref. В обоих случаях «вытащенное» значение — обычное, не реактивное. Разница только в API: у ref всё живёт за `.value`, у reactive — за полями объекта.

## Когда нужна связь

- Работай напрямую с ref: `counter.value` и при необходимости `counter.value.value`, без присваивания в отдельную переменную для отображения.
- Если значение пришло из `reactive`, а нужно «вынести» его с сохранением реактивности — используй `toRef` / `toRefs` (см. кейс toRef/toRefs). Для самого ref аналога toRef нет: ref уже и есть одна реактивная ячейка; «половину» ref вытащить реактивно нельзя.

## Что важно помнить

- Присваивание `ref.value` (или вложенного поля) в переменную даёт копию, не связь.
- Менять нужно сам ref через `.value`; тогда обновятся все, кто от него зависит.
- Переменная-копия обновляется в UI только при ререндере, когда компонент заново читает её значение.

## Термины и ссылки

- **`ref()`** — реактивная ссылка на значение, доступ через `.value`. [Документация](https://vuejs.org/api/reactivity-core.html#ref)
- **`toRef()`** — создаёт ref, связанный с полем reactive-объекта (для случая «вытащить из reactive»). [Документация](https://vuejs.org/api/reactivity-utilities.html#toref)
