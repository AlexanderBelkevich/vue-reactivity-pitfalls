> **По-простому:** `shallowRef` отслеживает только **замену** `.value`. Изменения внутри объекта (поля, массив и т.д.) не триггерят реактивность, пока ты не заменишь весь объект или не вызовешь `triggerRef`.

## Код

```javascript
const data = shallowRef({ count: 0 })

data.value.count += 1   // Vue не видит изменения ❌
triggerRef(data)        // принудительно сообщаем об изменении ✅
data.value = { count: 1 }  // замена .value — Vue видит ✅
```

## Как тестировать

- Нажми «count++ (без triggerRef)» — значение внутри объекта изменится, но watch не сработает и UI может не обновиться.
- Нажми «triggerRef(data)» — Vue принудительно пересчитает зависимости от этого shallowRef; watch сработает.
- Нажми «Заменить объект» — присваивается новый объект в `data.value`; замена отслеживается, watch сработает.

Ожидаемо: без замены `.value` или без `triggerRef` внутренние изменения не считаются изменением реактивного источника.

## Почему так происходит?

`ref` по умолчанию делает значение глубоко реактивным: если в `.value` лежит объект, Vue оборачивает его в reactive и отслеживает все вложенные поля. Это удобно, но для больших или редко меняющихся структур — лишние затраты.

`shallowRef` не оборачивает содержимое `.value` в proxy. Он хранит переданный объект «как есть» и отслеживает только саму ссылку: поменялась ли она. То есть реактивность срабатывает при присваивании `data.value = новыйОбъект`, но не при `data.value.count++`. Для Vue «источник» — это сам shallowRef и его `.value`; что внутри объекта, система не отслеживает.

Если ты мутируешь объект внутри и хочешь, чтобы Vue отреагировал, нужно либо заменить объект целиком (`data.value = { ...data.value, count: data.value.count + 1 }`), либо явно сказать Vue: «перепроверь этот ref» — для этого служит `triggerRef(data)`.

## Когда полезен shallowRef

- Большие объекты (например, экземпляры сторонних библиотек, тяжёлые структуры данных), где глубокое отслеживание не нужно или дорого.
- Когда обновления происходят «пакетами»: ты меняешь внутренность объекта, а потом один раз вызываешь `triggerRef`, и Vue обновляет всё зависимое.
- Когда логика всегда заменяет объект целиком, а не мутирует поля — тогда shallowRef ведёт себя предсказуемо и без лишнего проксирования.

## watch с deep: true и shallowRef

В демо используется `watch(data, ..., { deep: true })`. Важно: `deep` здесь относится к тому, что Vue при срабатывании watch будет заходить во вложенные поля при сравнении/отслеживании, но **срабатывание** watch для shallowRef по-прежнему происходит только при смене ссылки `.value` или при `triggerRef`. То есть `deep` не превращает shallowRef в глубокий ref; он влияет на то, как watch следит за значением после того, как источник «изменился». Для shallowRef «изменение» — это новая ссылка или triggerRef.

## Что важно помнить

- `shallowRef` реагирует на замену `.value` и на вызов `triggerRef`, но не на мутации внутри объекта.
- Если меняешь поля внутри — либо заменяй объект целиком, либо вызывай `triggerRef` после изменений.
- Используй shallowRef там, где глубокое отслеживание не нужно, чтобы не платить за него производительностью.
