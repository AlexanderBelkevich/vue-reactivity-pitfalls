> **По-простому:** `markRaw` помечает объект так, что Vue **не делает его реактивным**. Изменения внутри такого объекта не отслеживаются и не триггерят обновления. Полезно для сторонних инстансов и тяжёлых структур, но легко забыть и ждать реактивности там, где её нет.

## Код

```javascript
const rawConfig = markRaw({ theme: 'light' })
const state = reactive({ config: rawConfig })

state.config.theme = 'dark'  // watch не сработает, UI не обновится ❌
state.config = { theme: 'neon' }  // замена поля state — сработает ✅
```

## Как тестировать

- Нажми «theme = dark» — значение внутри `state.config` изменится, но watch на `state.config.theme` не сработает и UI может не обновиться, потому что сам объект config помечен как raw.
- Нажми «Заменить config» — в `state` присваивается новый объект в поле `config`; это уже изменение реактивного объекта `state`, поэтому watch сработает.

Ожидаемо: изменения внутри помеченного `markRaw` объекта не триггерят реактивность; замена самого поля в reactive — триггерит.

## Почему так происходит?

Vue при встрече с объектом в реактивном дереве (например, внутри `reactive` или в `ref`) по умолчанию оборачивает его в proxy, чтобы отслеживать чтения и записи. Но некоторые объекты не должны становиться реактивными: экземпляры сторонних классов, большие неизменяемые структуры, объекты с циклическими ссылками или с полями, которые не должны быть проксированы.

`markRaw` помечает объект специальным внутренним флагом. Vue при обходе и создании proxy проверяет этот флаг и **пропускает** такой объект: не оборачивает его, не отслеживает вложенные поля. Объект хранится «как есть». Поэтому когда мы делаем `state.config.theme = 'dark'`, мы меняем поле обычного объекта; реактивная система к нему не подключена и не видит изменения. Зато присваивание `state.config = { theme: 'neon' }` — это изменение поля самого реактивного объекта `state`, и оно отслеживается.

## Когда использовать markRaw

- Хранишь в состоянии экземпляр класса или объект из сторонней библиотеки (например, экземпляр карты, редактора, движка), который не должен быть обёрнут в proxy.
- Большие структуры данных, которые не должны реагировать на каждое внутреннее изменение, или объекты с особыми требованиями (getters/setters, замороженные объекты).
- Когда вложенный объект по смыслу «конфиг» или «внешняя зависимость», и тебе важна только замена целиком, а не реактивность полей внутри.

## Частая ошибка

Пометили объект как raw для оптимизации или из-за несовместимости с proxy, но в коде или в шаблоне ожидаем, что при изменении полей этого объекта обновятся computed, watch или UI. В таком случае реактивности не будет: нужно либо не использовать markRaw для этого объекта, либо реагировать только на замену объекта (например, следить за `state.config` и при смене подставлять новый объект).

## Связь с shallowRef

И `markRaw`, и `shallowRef` позволяют ограничить глубину реактивности. Разница: `markRaw` — «этот объект нигде не оборачивать в proxy» (он может лежать внутри reactive/ref, но сам остаётся сырым). `shallowRef` — «реактивна только замена `.value`», при этом сам объект в `.value` по умолчанию не оборачивается в deep reactive. Для вложенных в reactive объектов, которые не должны быть реактивными, используют именно `markRaw`.

## Что важно помнить

- `markRaw` исключает объект из реактивной системы; изменения внутри не отслеживаются.
- Используй для сторонних инстансов и структур, которые не должны быть proxy.
- Если помечаешь объект как raw, не ожидай реактивных обновлений при изменении его полей — только при замене самой ссылки в реактивном дереве.
